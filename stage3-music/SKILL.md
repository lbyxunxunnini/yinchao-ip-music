# 阶段 3：生歌

目标：把阶段 2 的歌词与曲风变成可播放的 AI 歌曲。调用本 skill 自带的生歌脚本，默认生成 **2 个版本**，下载 MP3 到本地，向用户展示歌名、试听链接与完整歌词。

本阶段只做「完整歌曲生成」。不做参考音频创作、歌曲续写、不经搜索分析流程的裸歌词请求（启动路径 1 的歌词曲风生成不在此列）。

## 输入

**前置门禁**：生歌前必须先确认阶段 2 验收已通过——用户已预览并接受歌词与曲风。未验收（未展示给用户确认）的歌词曲风不得提交生歌；用户打回修改后，必须重新展示并确认后才可提交。

- 标准模式：阶段 2 已验收的歌词与曲风文件：
  - `{位置}/{目标名}/songs/{目标名}-{歌名}-歌词.md`（取「歌词」部分）
  - `{位置}/{目标名}/songs/{目标名}-{歌名}-曲风.md`（取「曲风描述」部分）
- 直接模式：用户直接给出歌词与曲风描述（未走阶段 1/2 时）。

组装后确认约束：歌词 ≤ 3000 字符、曲风 ≤ 1000 字符（脚本提交前会再次校验）。

## 生歌前检测 API Key

生歌前先确认环境变量 `YINCHAO_API_KEY` 已配置（检测方式与缺 Key 引导文案见主 SKILL.md「API Key 检测」章节）。缺 Key 时展示引导，配置完成后继续；已配置则直接生歌，不索取、不回显、不记录完整密钥。

## 执行

脚本从本 skill 根目录调用（`$SKILL_ROOT` 为本 skill 目录）。**传参方式**：

- 歌词/曲风内容简单（无引号、`$`、反引号、换行等特殊字符）时，可直接内联传参：

```bash
python3 "$SKILL_ROOT/scripts/yinchao_music.py" song \
  --prompt "{曲风描述}" \
  --lyric "{歌词}" \
  --title "{歌名}" \
  --n 2 \
  --output-dir {位置}/{目标名}/audio \
  --name-prefix "{目标名}-"
```

- 歌词/曲风含特殊字符（引号、`$`、反引号）或为多行文本时，**必须先用临时文件传参**（先把歌词/曲风的纯文本内容写入临时文件，再传入文件路径），避免 shell 解析失败或内容被破坏：

```bash
python3 "$SKILL_ROOT/scripts/yinchao_music.py" song \
  --prompt-file {临时文件}/prompt.txt \
  --lyric-file {临时文件}/lyric.txt \
  --title "{歌名}" \
  --n 2 \
  --output-dir {位置}/{目标名}/audio \
  --name-prefix "{目标名}-"
```

- 默认 `--n 2`（两个版本）；用户明确只要一首时用 `--n 1`。
- `--title` 传阶段 2 定稿歌名：服务端未返回歌名时，用它作为文件名与展示兜底（alpha 测试环境实测服务端 title 为空）。
- `--output-dir` 传 `{位置}/{目标名}/audio`；未传时脚本默认当前工作目录下的 `audio/`，因此主上下文必须显式传参，保证产物落在约定目录。
- 脚本输出 JSON：`songs[]` 中 `status: "done"` 的项含 `title`、`audio_url`、`lyric`、`mp3_path`（文件名含版本序号 `-v1`/`-v2`）；失败项含 `error`。

## 长任务与中断恢复

- 默认等待完成（普通歌曲通常约 90～180 秒）。等待期间不刷屏，只在开始时告知用户正在创作。
- 需要稍后查看时加 `--no-wait`，脚本返回任务 ID；稍后用 status 继续查询原任务：

```bash
python3 "$SKILL_ROOT/scripts/yinchao_music.py" status \
  --task-id "{任务 ID}" \
  --n 2 \
  --output-dir {位置}/{目标名}/audio \
  --name-prefix "{目标名}-"
```

`--n` 必须与提交时一致（提交用 `--n 1` 时，恢复查询也传 `--n 1`）；`--n` 是等待的版本数，与提交数不符会一直轮询到超时。

`--task-id` 可省略：脚本自动读取 `{位置}/{目标名}/audio/.task-latest.json` 中的最近任务记录（song 提交时自动写入，任务成功完成后自动删除）。会话重启后即使对话中的 task_id 丢失，也能从该文件找回。

- 超时、中断、查询失败时都保留任务 ID 并继续查询原任务，**不重新提交**（避免重复扣费/重复生成）。

## 结果交付

歌曲成功后，逐版本展示（不展示原始 JSON）：

- 歌名
- 试听/下载链接（`audio_url`）
- 完整歌词
- 本地 MP3 路径（`mp3_path`）

```markdown
## 版本 1 ·《{歌名}》

[试听或下载歌曲]({audio_url})

本地文件：`{mp3_path}`

### 歌词

{完整歌词}
```

只有一个结果时省略「版本 1」。只有歌词曲风（启动路径 1）时，不进入本阶段。

## 版本选择

两个版本都展示给用户后，由用户选定：

- **选定版本**：阶段完成；未选版本保留在 audio/ 目录，不删除（用户可自行处理）。
- **都不满意**：取得用户明确授权后重新生成（视为一次新的付费尝试），不静默重复调用。
- **只留一首**：用户明确要求时，可保留选定版本、删除未选版本（删除前说明）。

## 失败处理

- API Key 缺失或无效：引导配置（见主 SKILL.md），不让用户把 Key 发到聊天中。
- 免费额度或余额不足：请用户前往音潮开放平台检查账户。
- 歌词或曲风不合要求：说明需要修改的具体内容，回阶段 2 修改后重试。
- 内容未通过安全审核：请用户调整主题或表达后再试。
- 请求频繁或服务暂时不可用：建议稍后继续，不盲目重复提交。
- 任务失败、取消或响应缺少音频：向用户说明可理解的失败原因，不伪造结果。

## 禁止

- 不得伪造歌名、试听地址、MP3 文件或任务状态。
- 不得绕过脚本直接调用音潮 API。
- 不得在未取得新授权时重复提交同一任务或静默重新生成。
- 不得把失败日志或任务 ID 冒充音频交付。
